## 4.1 Compressed configurations

Program: src/compression_experiment.py. Checks: sql/09_compression_checks.sql. Run 2026-10-08 CAT.
Chunk interval: 1 day (chosen in Section 3). Baseline: energy_readings (uncompressed, same indexes).

| Table | orderby | segmentby | Indexes |
|---|---|---|---|
| energy_time_compressed | event_time DESC | (none) | btree (event_time DESC); btree (meter_id, event_time DESC) |
| energy_meter_compressed | event_time DESC | meter_id | btree (event_time DESC); btree (meter_id, event_time DESC) |

- Columnstore enabled with ALTER TABLE ... SET (timescaledb.enable_columnstore = true, timescaledb.orderby, timescaledb.segmentby) (TimescaleDB 2.30.2).
- Policies: add_columnstore_policy(after => 48 hours); jobs 1000 and 1001 paused (scheduled = false) until 4.3 was complete.
- Experiment start 2026-10-08 18:20:04 CAT; one cutoff for both tables = start - 48 h = 2026-10-06 18:20:04 CAT.
- Each of the 29 baseline chunk ranges was copied separately, then compressed manually with
  convert_to_columnstore if its range end preceded the cutoff (all 29 did). Compression was timed separately from loading.
- The same 29 chunk ranges are compressed in both tables. Data checks repeated from 3.1: 10,643,735 rows,
  4,000 meters, 2026-09-01 00:00 to 2026-09-28 23:45, sum power_kw 15,414,817.387792,
  sum energy_kwh 3,853,704.346816 in all three tables (exactly equal).

## 4.2 Storage and compression cost

| Table | Data MB | Index MB | Total MB | Compression ratio | % saved | Compressed chunks | % rows in compressed chunks | Compression time (s) |
|---|---|---|---|---|---|---|---|---|
| energy_readings (baseline) | 950.9 | 405.8 | 1,356.7 | 1.00 | 0.0 | 0/29 | 0.00 | - |
| energy_time_compressed | 437.8 | 0.9 | 438.7 | 3.09 | 67.7 | 29/29 | 100.00 | 58.3 |
| energy_meter_compressed | 496.2 | 5.5 | 501.6 | 2.70 | 63.0 | 29/29 | 100.00 | 116.7 |

Ratio = baseline total / compressed total. % saved = 100 x (baseline - compressed) / baseline.
Sizes include all chunks (compressed and uncompressed) and their indexes (hypertable_detailed_size).
Row percentage uses the original row counts of the compressed chunks (compression_log) / 10,643,735.
Loading time is excluded from the compression time: load 241.7 s (time) and 238.9 s (meter).

Observations: time-only compression is smaller (3.09x vs 2.70x) because it packs full 1,000-row
batches, whereas meter segmentation creates about 95-row batches per meter per day with more per-batch
metadata. Meter segmentation also doubles compression cost (116.7 s vs 58.3 s) because each chunk is
split into 4,000 groups compressed separately. Row-level indexes are not kept on compressed chunks
(index size 406 MB -> 1-6 MB), which is a large part of the saving.
