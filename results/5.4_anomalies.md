## 5.4 Abnormal consumption

Program: src/analysis_5_4.py (run 2026-10-08 19:34 CAT, 258 s) on cleaned energy_readings.
Outputs: results/5_4_flags.csv, 5_4_event_evaluation.csv, 5_4_summary.csv, figures/5_4_anomaly_examples.png.

### Detection rule (fixed before using the labels)
- Baseline: median power_kw of the same meter, same CAT 15-minute time of day, same day type
  (weekday / weekend) over the 28 days: 768,000 baselines, each from 5-20 readings.
- Ratio = power_kw / baseline. Flag a reading if ratio >= 2.0 (high) or <= 0.3 (low).
- Reasons: comparing each meter with itself removes differences between customers (an industrial meter
  uses about 17x a household); matching time of day and day type removes the daily and weekly cycles; the
  median ignores the few anomalous values instead of being pulled by them.
- Threshold choice from the distribution of ratios over all readings (no labels used): 0.01 % = 0.765,
  1 % = 0.822, median = 1.000, 99 % = 1.199, 99.99 % = 1.294. Normal readings stay within about +/-25 % of
  their baseline, so 2.0 and 0.3 lie far outside normal variation while still catching a doubling or a
  70 % collapse in demand.

### Missed events and false alarms
- No event was missed because every injected event changed power by a large factor (ratios about 2.4-3.4 for
  spikes, about 0.02-0.04 for drops) for three hours. An event would be missed if all its readings were missing,
  or if a real anomaly were milder than the thresholds (e.g. +50 % demand), which is the trade-off of
  conservative thresholds.
- No false alarms occurred because normal simulated noise is bounded (max ratio 1.29, min 0.77) and the
  baseline removes daily, weekly and customer differences. Real data would produce false alarms from
  holidays, weather, legitimate changes in a customer's usage, and weekend baselines built from only 5-8
  days. For live use: require two or more consecutive flagged intervals, use a rolling 4-week baseline,
  and add holiday/calendar information.
