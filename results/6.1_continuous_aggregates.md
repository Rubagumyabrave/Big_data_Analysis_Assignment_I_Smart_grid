## 6.1 Continuous aggregates

SQL: sql/12_continuous_aggregates.sql (views), src/caggs_refresh.py (refresh, sizes, policies),
sql/13_caggs_evidence.sql (definitions, samples, policies, job status). Source: cleaned energy_readings.

| View | Bucket | Group key | Stored columns |
|---|---|---|---|
| energy_15min_region | time_bucket('15 minutes', event_time, 'Africa/Kigali') | region (inner join meters) | energy_kwh = sum(energy_kwh), power_kw_sum = sum(power_kw), reading_count = count(*) |
| energy_hourly_region | time_bucket('1 hour', event_time, 'Africa/Kigali') | region (inner join meters) | same |
| energy_daily_meter | time_bucket('1 day', event_time, 'Africa/Kigali') (CAT midnight) | meter_id | same |

All three created WITH NO DATA (initially empty) and with timescaledb.materialized_only = true
(real-time aggregation disabled), so queries read only stored buckets.

### Refresh policies (added at 19:47:59 CAT, after the measurements)
start_offset 3 days, end_offset 1 hour, schedule_interval 15 minutes; jobs 1002, 1003, 1004.
The window is relative to the database clock (October 2026), so the policies only refresh roughly the
last three days before now minus one hour; they cannot populate the September data, which is why
the full period was refreshed manually.
