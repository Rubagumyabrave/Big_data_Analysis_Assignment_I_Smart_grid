## 2.3 Cleaning duplicate readings

Script: sql/05_clean_duplicates.sql (repeatable; a second run deletes nothing). Run 2026-10-08 CAT.

### Investigation
- Duplicate groups (same meter_id and event_time): 53,113, each with exactly 2 copies.
- All 53,113 groups are identical in received_time, power_kw, voltage_v, current_a, frequency_hz
  and energy_kwh. Conflicting groups: 0, so no investigation of conflicting values was needed.
- Method: number the copies in each group with row_number() and delete copies 2+ by their
  physical row identity (chunk tableoid + ctid) inside one transaction.

### Before and after

| | Rows | Total energy_kwh |
|---|---|---|
| Before cleaning | 10,696,848 | 3,872,863.893179 |
| After cleaning | 10,643,735 | 3,853,704.346816 |
| Difference | 53,113 | 19,159.546363 |

- Final row count = expected_counts.unique_readings (10,643,735). Remaining duplicate pairs: 0.
- Energy removed (19,159.546363 kWh) equals the energy of the extra copies computed before
  deletion, so only duplicate copies were removed. Keeping them would overstate consumption by about 0.5 %.
- VACUUM ANALYZE was run afterwards to reclaim space and refresh planner statistics.

### Why missing readings must not become zero
The 108,265 missing readings are left as gaps. A missing reading means the consumption for that
15-minute interval is unknown, not that it was zero: the meter was almost certainly still drawing
power, but the reading was lost in transmission. Filling gaps with 0 would:
1. understate energy totals for the affected meters, regions and days;
2. create false "unusual drop" anomalies in 5.4, because a zero looks like a sudden collapse in demand;
3. bias the forecast in Section 8 downwards, because the model would learn from fake low values;
4. hide the data quality problem: completeness would look like 100 % when it is really 98.99 %.
Keeping gaps lets every later analysis report the true observed values and their completeness.

This cleaned energy_readings table is the common dataset for every later experiment.
